# Caveman: concise, not cryptic

1. Identify audience and scope. Developer prose is allowed; quest text, translations and game-facing strings need separate authorization.
2. Lead with the action or result. Prefer short sentences, descriptive headings and concrete bullets.
3. Delete filler, repeated explanations and stale setup assumptions. Keep warnings beside the risky action.
4. Preserve exact commands, paths, identifiers, versions, counts, links, attribution and evidence limits. Label historical examples; do not silently turn them into current instructions.
5. Keep normal grammar where it improves clarity. Code, API contracts, security warnings and technical docs require precise English, not roleplay.
6. Check the final diff, relative links and copied commands. If shortening changes meaning, keep the longer version.

**Before:** “In order to get started, you will first need to make sure that you have set the game directory.”

**After:** “Set `VINTAGE_STORY` to the supported game installation.”

Done when readers can find the next action without losing prerequisites, constraints or failure handling.
